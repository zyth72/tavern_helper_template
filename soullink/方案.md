# SoulLink 改造方案：推演时给每个角色注入 ANIMA 专属记忆

> 项目定位：fork [SoulLink](https://github.com/Rosa9527/SoulLink)（SillyTavern 前端插件），在其"剧情前置 NPC 推演"（多 agent 角色扮演）中接入 ANIMA 记忆系统，让每个角色推演时获得自己的 ANIMA 专属记忆。
> 本文档为完整方案，直接照此实施，无需再次讨论方案本身。

---

## 0. 背景与动机

- 玩法：港区聊天（修通过手机消息与舰娘互动），时间/排班/乱入检定由现有"值班与乱入"脚本负责。
- 目标：多 agent 角色扮演——按场景分割角色、每个角色单独扮演（便宜模型）、好模型合成正文。
- 已验证：SoulLink 已在标准 SillyTavern 前端插件内跑通"发送前预筛 → 各角色并发推演 → 注入 → 主模型生成"链路，**不需要服务器插件，也不需要 TauriTavern**。
- 速度：早期多 agent 慢是模型速度问题；DeepSeek V4 足够快，可接受并行推演。
- 本次改造范围（第一刀）：**仅"角色推演时给每个角色注入 ANIMA 专属记忆"**，其余保持 SoulLink 原样。

## 1. SoulLink 关键架构（已核实，行号基于 v1.3.1 index.js）

### 1.1 多 agent 推演流程

```
用户点击发送
  → messageSent 事件（阻塞监听，第 279 行附近）
  → 角色预筛 Gate（roleplayPreScreen 提示词，高频轻量调用）
      只给：<Registered_Characters> 名单 + <Recent_Messages> 最近消息
      返回：{ "characters": ["凛", "贝法", ...] }（最多 6 个，按戏份排序）
  → 各角色独立并发推演（roleplaySystem 提示词）
      每个角色 = 一次独立 API 调用（受 API 并发限制，默认 3）
  → 推演结果按统一格式注入到最后一条用户消息正下方
      （setExtensionPrompt / <NPC_Deduction> 块，每轮结束自动清空）
  → 恢复发送，交给主模型生成
```

## 2. 改造方案

### 2.1 目标

推演时每个角色的输入中加入 `<Anima_Memory>` 块（该角色的 ANIMA 专属历史记忆），让子 agent 在推演时能调用角色自己的长期记忆，增强扮演一致性。

### 2.2 改造后的推演输入结构

```
messages = [
  { role: 'system', content: roleplaySystem 提示词 },
  { role: 'user', content: 引导语（<Character_Profile>） },
  { role: 'user', content: `<Character_Profile>...档案...</Character_Profile>` },
  { role: 'user', content: 引导语（<Anima_Memory>：该角色记住的历史记忆，属于 TA 已知信息） },   ← 新增
  { role: 'user', content: `<Anima_Memory>...记忆...</Anima_Memory>` },                          ← 新增
  { role: 'user', content: 引导语（<Recent_Messages>） },
  { role: 'user', content: `<Recent_Messages>...最近消息...</Recent_Messages>` },
  { role: 'user', content: 扮演指令 },
]
```

### 2.3 新增函数

```js
// 1. 调 ANIMA 后端 /query 检索记忆，按人物 tags 过滤
async function fetchAnimaMemoryForCharacter(name, searchText) {
  // searchText: 用最近消息/剧情摘要拼接的检索词
  const res = await fetch(`${animaApiUrl}/query`, {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      searchText,
      chatContext: { ids: [animaCollectionId], strategy: null },  // 集合 id 见待确认项 2
      kbContext: { ids: [], strategy: null },
    }),
  });
  const data = await res.json();
  const all = [...(data.chat_results || []), ...(data.kb_results || [])];
  const tags = (item) => item.tags || [];
  return {
    专属: all.filter(item => tags(item).includes(name)),        // 人物标签含本角色名
    公共: all.filter(item => tags(item).includes('public')),     // 公开记忆
  };
}

// 2. 在 buildNpcDeductionCharacterMessages 中插入 <Anima_Memory> 块（异步化该函数）
```

### 2.4 数据流

```
用户发送 → 预筛出角色名单
  → 对每个角色：buildNpcDeductionCharacterMessages(name, archive, prompt)
      ├── 读取角色档案（原有）
      ├── fetchAnimaMemoryForCharacter(name, 剧情摘要)   ← 新增
      │     └── GET/POST anima-rag /query → 按 tags 过滤出 专属+公共 记忆
      └── 组装 <Character_Profile> + <Anima_Memory> + <Recent_Messages>
  → 并发推演 → 注入 <NPC_Deduction> → 主模型生成
```

### 2.5 改动文件清单

- `index.js`（唯一改动文件，约 60-100 行新增/修改）
  - 新增 `fetchAnimaMemoryForCharacter`
  - 修改 `buildNpcDeductionCharacterMessages`（异步 + 插入记忆块）
  - 修改 `deduceNpcCharacter`（调用处适配异步）
  - 设置项：ANIMA API 地址、集合 id、注入开关（待确认项 1/2/4）
- `settings.html`（可选）：ANIMA 配置项 UI

## 3. 待确认项（实施前定，默认值见括号）

1. **ANIMA API 地址获取方式**：SoulLink 设置页手动填 Base URL（推荐，默认 `http://127.0.0.1:8000/api/anima-rag` 之类） vs 自动读 ANIMA 前端扩展设置（免配置但耦合）。
2. **集合 id（chatContext.ids）来源**：复刻 ANIMA 的 `getSmartCollectionId` 算法（chatId → 集合名） vs 设置项手动填 vs 前端扩展读取。→ 建议先手动填，后续自动。
3. **`<Anima_Memory>` 语义**：声明为"该角色记住的历史记忆，属于 TA 已知信息，与档案 memory 分节并存（档案管设定+近期，ANIMA 管历史）"。是否需要限制记忆条数（建议每角色最多 5 条，控制 token）。
4. **注入开关**：设置项"注入 ANIMA 记忆"（默认关，跑通后开）。避免影响现有 SoulLink 使用。

## 4. 实施步骤

1. fork SoulLink → 本地 clone（独立项目目录）。
2. 先跑通原版：导入酒馆，注册角色，确认推演功能正常（基线）。
3. 加设置项（ANIMA API 地址、集合 id、开关），默认关闭。
4. 实现 `fetchAnimaMemoryForCharacter`（先写死地址/集合 id 联调 /query，确认能取到带 tags 的记忆）。
5. 改 `buildNpcDeductionCharacterMessages` 插入 `<Anima_Memory>`（开关控制），异步化调用链。
6. 联调：开启开关 → 发送消息 → 观察推演请求体里是否含 `<Anima_Memory>`、记忆是否按人物正确分配。
7. 测试：单角色/多角色、无记忆（返回空）、/query 失败（降级为不注入，不影响推演）。
8. 按需做「合成正文」扩展（第二阶段，不在本次范围）。

## 5. 测试与验收

| 用例 | 预期 |
|---|---|
| 推演请求体含 `<Anima_Memory>` | 该角色专属记忆（tags 含角色名）+ 公共记忆 |
| 记忆为空 | 不注入该块，推演正常 |
| /query 超时/失败 | 降级，推演照常（try-catch 包裹） |
| 角色 A 的记忆不含角色 B 的内容 | 反全知（人物标签过滤生效） |
| 开关关闭 | 行为与原版完全一致 |

---

## 6. 风险与回退

- **token 增加**：每个角色多一段记忆（≤5 条，控制长度），推演输入变大 → 可调记忆条数/长度限制。
- **记忆污染**：若人物标签不准，记忆分配错 → 依赖 ANIMA 总结提示词的 visible_to/retrieval_tags 质量（ANIMA 侧文档有说明）。
- **改动可控**：单文件、开关默认关、失败降级 → 可随时回退。
