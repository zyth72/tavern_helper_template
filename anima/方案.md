# ANIMA 对接方案：为 agent-play 插件提供按人物的记忆查询

> 项目定位：ANIMA 记忆系统（前端扩展 `Anima-Memory-System` + 后端插件 `anima-rag`）为 agent-play 插件的角色推演提供"按人物过滤的记忆"能力。
> 本文档为完整方案，直接照此实施。

---

## 0. 背景

agent-play 插件 做多 agent 角色扮演（每个角色单独推演），需要给每个角色注入 TA 自己的长期记忆。ANIMA 已经具备：记忆总结（带人物标签）、向量化 + BM25 检索、RAG 查询。本项目的目标是确认/打通"按人物查询记忆"这条链路，并暴露给 agent-play 插件。

关键结论（已核实）：**后端零改动即可在客户端按人物过滤记忆**；可选做一个小后端改造（`/query` 加 tagFilter）提升召回。

---

## 1. ANIMA 架构现状（已核实）

### 1.1 位置

- 前端扩展：`SillyTavern-Launcher/SillyTavern/public/scripts/extensions/third-party/Anima-Memory-System/`
- 后端插件：`SillyTavern-Launcher/SillyTavern/plugins/anima-rag/`

### 1.2 技术栈（后端）

- `vectra`（向量索引）+ `minisearch`（BM25）+ `jieba-wasm`（中文分词）+ `zod`
- 核心文件：`index.js`（3746 行）、`bm25_engine.js`（986 行）
- Express 路由挂载方式：`module.exports = { init(router) { ... } }`（SillyTavern 后端插件标准）

### 1.3 关键端点

| 端点 | 作用 |
|---|---|
| `POST /insert` | 写入记忆（text + tags + timestamp + collectionId + index + batch_id） |
| `POST /query` | 查询记忆（searchText 向量 + bm25SearchText + chatContext/kbContext + sessionId 等）→ 返回 `{chat_results, kb_results}` |
| `POST /bm25/query` 等 | BM25 专项 |
| `POST /import_collection` / `export_collection` | 集合导入导出 |

### 1.4 记忆链路（已确认全程打通）

```
总结提示词（用户自定义）生成 summaries[].tags.retrieval_tags（含角色名）
  → summary_logic.js（963-986 行）把 tags 对象展开成数组
  → 存入世界书条目 extra.history[].tags
  → rag_status.js 调 insertMemory(text, item.tags, ...)（179 行）
  → rag_logic.js insertMemory → callBackend('/insert', { tags })
  → 后端 index.js /insert → metadata.tags（已索引：metadata_config indexed: ["tags","index","batch_id"]）
  → /query 返回每条记忆带 tags（index.js 226 行：tags: metadata?.tags）
```

**结论：`/query` 返回的记忆自带人物标签（角色名 tags），客户端（agent-play 插件）可直接按 tags 过滤分配。后端无需改动。**

## 2. /query 接口细节（已核实）

### 2.1 入参

```jsonc
{
  "searchText": "剧情检索词（向量化）",
  "bm25SearchText": "BM25 检索词（可省）",
  "apiConfig": { "apiurl": "...", "key": "...", "model": "..." },   // 向量模型配置
  "chatContext": { "ids": ["集合id"], "strategy": null },
  "kbContext": { "ids": [], "strategy": null },
  "ignore_ids": [],
  "echoConfig": {},
  "sessionId": null,
  "is_swipe": false,
  "rerankConfig": { "enabled": false },
  "bm25Configs": {}
}
```

### 2.2 出参（每条记忆）

```jsonc
{
  "chat_results": [ { "text": "...", "tags": ["凛", "Important"], "index": "...", "timestamp": ... }, ... ],
  "kb_results": [ ... ]
}
```

### 2.3 底层能力（可能用到的改造点）

- `queryIndexSafe(indexInstance, vector, k, filter)`（568 行）：vectra 查询已支持 metadata filter。
- `buildFilter({ tags: { $in: [label] } })`（692 行定义，971/1021/1054/1090/1118 行已有使用）：**按 tags 过滤是现成能力**（动态策略里已在用）。
- 但 `/query` 端点目前**未暴露 filter/tagFilter 参数**给外部调用方。

## 3. 对接方案

### 3.1 方案 A（零改动，优先实施）

agent-play 插件 侧（见 `agent-play/方案.md`）：

```
一次 /query 检索 N 条（N 建议 10-20）
  → agent-play 插件 按 tags 过滤：
      tags 含角色名 → 该角色专属记忆
      tags 含 "public" → 公共记忆（所有角色共享）
  → 组装 <Anima_Memory>
```

优点：后端不动；缺点：top-N 里某角色可能没被召回，导致该角色分不到专属记忆（随机性）。

### 3.2 方案 B（后端小改，可选，解决召回）

在 anima-rag `index.js` 的 `/query` 端点加可选入参 `tagFilter: string[]`：

```js
// /query 解构处（2145 行附近）加：
const { ..., tagFilter } = req.body;

// 在查询链（queryMultiIndices / performDynamicStrategy）调用处，
// 将 tagFilter 转换为 buildFilter({ tags: { $in: tagFilter } }) 传入
//（需透传到的调用点：queryMultiIndices 的 filter 参数，约 600/658/971 行附近）
```

效果：`searchText + tagFilter: ["凛"]` → 只检索 tags 含"凛"的记忆，保证召回。

### 3.3 集合 id（chatContext.ids）来源

ANIMA 前端 `getSmartCollectionId()`（rag_logic.js / worldbook_api.js 中）把当前 chatId 转换成集合 id（含后缀处理与命名逻辑）。agent-play 插件 获取集合 id 的方式：

1. 手动设置（agent-play 插件 设置项填集合 id，最简单，先做）；
2. 复刻 `getSmartCollectionId` 算法（读 ANIMA 前端源码拷贝）；
3. 读 ANIMA 前端扩展的设置/变量（耦合）。

→ 建议先 1，后续 2。

### 3.4 ANIMA API 地址暴露

agent-play 插件 需要知道 anima-rag 后端地址。SillyTavern 插件后端默认挂载在酒馆服务下（如 `/api/anima-rag` 或类似路径）。**实施前需在酒馆里确认 anima-rag 的实际挂载路径**（看 SillyTavern 插件加载日志或访问 `/api/anima-rag/...` 探测）。

## 5. 实施步骤

---

## 6. 风险

- 记忆插入时 tags 是否真的含角色名，取决于总结提示词的 `visible_to`/`retrieval_tags` 质量——用户现有总结提示词已正确生成人物标签（已验证）。
- `["public"]` 记忆对所有人可见；私密记忆靠"人物标签不含你"来隔离。
- 记忆量大时 /query 耗时增加（向量检索本身快，重排可选关闭）。
