# agent-play 插件方案：多 agent 角色扮演（前后端分离，接入 ANIMA）

> 项目定位：标准 SillyTavern 的多 agent 角色扮演系统——**前端插件 + 服务器插件配合**，主预设改造为"主 agent 模式"（改法 1：主模型可调用子 agent），角色由子 agent 并发扮演（便宜模型），记忆接入 ANIMA（按人物隔离）。
> 参考 TauriTavern 的 agent 模块结构（run 控制器/重试/回滚/上下文策略），但**宿主层全部重写**为标准 SillyTavern 对接，**子 agent 并发扮演自研**（TauriTavern 没有）。
> 本文档为完整方案，直接照此实施。

---

## 0. 背景与动机

- 玩法：港区聊天（修通过手机消息与舰娘互动），时间/排班/乱入检定由现有"值班与乱入"脚本负责。
- 目标：多 agent 角色扮演——主 agent（正文模型）+ 子 agent（角色扮演，便宜模型并发）。
- 决策：
  - **前后端分离**：前端插件管酒馆交互（触发/组装/落笔/UI），服务器插件管 agent 计算（主循环/子并发/ANIMA 对接/事件流）。
  - **主预设改造 = 改法 1**：主预设加"主 agent 模式"指令 + `<agent_call>` 调用标记；主模型照常生成，需要角色内心时输出 `<agent_call>`，插件拦截、跑子 agent、注入独白、继续生成。**主预设其余规则原样保留**。
  - **不 fork SoulLink**（问题多、未接 ANIMA）；**TauriTavern 参考模块结构、不依赖宿主**。
  - 记忆 = ANIMA，仅子 agent 层按人物隔离；主模型不直接查 ANIMA（防全知）。
  - 速度：DeepSeek V4 足够快，并行扮演可接受。

## 1. 架构总览（前后端分离）

```
┌─ 前端插件（extensions/third-party/agent-play/）────────────────┐
│  触发: GENERATION_AFTER_COMMANDS（非 automatic_trigger）       │
│  组装: 世界书关键字分配、最近消息、场景/时间/乱入上下文          │
│  拦截: 主模型输出的 <agent_call> 标记 → 调后端跑子 agent        │
│  注入: 子 agent 独白注入回提示词 → 主模型继续生成                │
│  UI: 设置面板、run 时间线                                     │
└──────────────┬───────────────────────────────────────────────┘
               │ fetch (/api/agent-play/*)
┌─ 服务器插件（plugins/agent-play/）────────────────────────────┐
│  子 agent 并发扮演（便宜模型, Promise.all + 并发限制）          │
│  主 agent 循环辅助（多轮 <agent_call> 编排, runId/事件流）      │
│  重试/回滚/超时/降级                                          │
│  ANIMA 对接（调 anima-rag /query, 按人物过滤）                │
└──────────────┬───────────────────────────────────────────────┘
               │
        ANIMA /query（复用 anima-rag 服务器插件）
```

**分工原则**：前端管"酒馆交互"（轻），后端管"agent 计算"（重）——ANIMA 同款模式。

## 2. 核心流程（改法 1：主 agent 模式）

```
用户发送消息
  → ① 前端注入"主 agent 能力"提示（主预设含 <agent_call> 用法说明）
  → ② 主模型照常生成正文（走酒馆主管线, 主预设全部规则生效）
        ┌─────────────────────────────────────────────┐
        │ 主模型输出 <agent_call characters="凛,贝法"   │
        │             focus="她们对修宣告贝尔自家人怎么反应"/> │
        │  → 前端拦截该标记                              │
        │  → 调后端 /api/agent-play/act                  │
        │  → 后端并发启动子 agent（便宜模型）:             │
        │     每个角色 = 世界书条目(关键字分配)            │
        │              + ANIMA 专属记忆(按人物)           │
        │              + 最近消息 + 剧情时间               │
        │  → 返回独白 { 凛: "...", 贝法: "..." }          │
        │  → 前端把独白 <NPC_Deduction> 注入提示词         │
        │  → 主模型继续生成（引用独白写正文）               │
        │  → 若又输出 <agent_call> → 再循环（最多 N 次）    │
        └─────────────────────────────────────────────┘
  → ③ 主模型完成正文（无 <agent_call> 或达轮数上限）
  → ④ 回写: 场景记录/存在时间由"值班与乱入"脚本负责
```

**主模型即主 agent**：它决定要不要调用子 agent、调谁、关注什么；插件只做"拦截标记 + 编排子 agent + 注入独白"。主预设其余规则（元叙事/时间/喝水平账/输出格式）全部照常。

## 3. 主预设改造（改法 1 的新增段落）

在主预设（Admin 规则区）加一段：

```
### Admin: 主 agent 模式
你是本轮剧情的主 agent。除直接写正文外，你可以调用"角色推演"子 agent 获取角色的真实内心与行动意图：
- 需要知道某角色对当前事件的心情/想法/下一步行动时，在你的回复中输出调用标记：
  <agent_call characters="角色名,角色名" focus="要推演的具体问题" />
- 调用标记不是正文，插件会拦截它并为你注入推演结果（独白），你继续写正文时引用即可。
- 日常剧情无需推演时，直接写正文，不要输出调用标记。
- 同一轮最多调用 {maxAgentCalls} 次。
```

其余规则不动。

## 4. 子 agent 输入组装（每个角色）

```
[system] 角色扮演子 agent 提示词（自定义模板, 含信息盲区/认知框架/行动推进要求）
[user]   主 agent 的关注点（focus）: "凛对'修宣告贝尔是自家人'的反应"
[user]   <Character_Worldbook>（该角色世界书条目 + 公共条目, 关键字分配）</Character_Worldbook>
[user]   <Anima_Memory>（该角色 ANIMA 专属记忆, 按人物过滤）</Anima_Memory>
[user]   <Recent_Messages>（最近 N 条消息）</Recent_Messages>
[user]   剧情时间（插件算好, 现实+7天）: 2026-08-18（周二）19:36
[user]   乱入/排班上下文（来自"值班与乱入"脚本变量）: 在场者/乱入候选/夜班持有者
[user]   扮演指令: "请扮演「凛」, 输出 JSON: { character, monologue }"
```

## 6. ANIMA 对接（记忆隔离, 仅子 agent 层）

### 6.1 原则
- **子 agent 层**：调 anima-rag `/query` → 按人物 tags 过滤 → 只注入"人物标签含该角色名"的记忆。
- **主模型**：不直接查 ANIMA（防全知）；独白是它接触记忆的唯一途径。
- **public 默认不注入**（存量脏标签）；后续可开"public 共享"开关。

### 6.2 取数（后端）
```js
async function fetchAnimaMemoryForCharacter(name, searchText) {
  const res = await fetch(`${animaApiUrl}/query`, {
    method: 'POST', headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({
      searchText, chatContext: { ids: [animaCollectionId], strategy: null },
      kbContext: { ids: [], strategy: null }, // apiConfig 待确认项 2
    }),
  });
  const data = await res.json();
  const all = [...(data.chat_results || []), ...(data.kb_results || [])];
  return all.filter(i => (i.tags || []).includes(name)).slice(0, memoryLimit);
}
```

### 6.3 重大事件库（可选, 二期）
- 独立集合（如 `major_events`），重大事件（L2 里程碑/L3/KEY_EVENT）写入；
- `/query` 时 `ids: [聊天库, major_events]` 双库并行（后端 `queryMultiIndices` 已支持）；
- 世界书"重大事件摘要"条目常驻（一行摘要, token 极小）——**当前日常为主、重大事件少，摘要 token 不用优化**；
- 写入方式待定（A: 改 ANIMA 总结分流 / B: 插件后台写入）。

## 7. 服务器插件模块结构（参考 TauriTavern, 自研）

```
plugins/agent-play/
├── package.json
├── index.js                 # init(router): 挂 /api/agent-play/* 端点
├── run-controller.js        # run 生命周期（runId/事件流/取消）——参考 TauriTavern agent-run-controller, 宿主重写
├── actor.js                 # 子 agent 并发扮演（Promise.all + 并发限制 + 超时降级）——自研
├── context-policy.js        # 上下文组装（世界书/记忆/消息/时间/乱入）——参考 TauriTavern agent-context-policy
├── prompt-assembly.js       # 扮演提示词组装——参考 agent-system-prompt, 内容按玩法定制
├── retry.js                 # 重试策略——参考 agent-run-retry
├── rollback.js              # 失败回滚——参考 agent-run-message-rollback, API 换成标准酒馆
├── events.js                # 事件流（runId + 订阅, 供前端时间线）——自研, 参考 TauriTavern 事件模型
└── anima-client.js           # ANIMA /query 对接 + 人物过滤
```

**关键改造点（相对 TauriTavern）**：
- `window.__TAURITAVERN__?.api.*` → 服务器插件自己的配置/存储（node）；
- ESM → CommonJS（或 node ESM）；
- 酒馆 API → 标准 SillyTavern 后端路由；
- **子 agent 并发扮演 = 自研**（TauriTavern 无此功能）。

## 8. API 端点

```
POST /api/agent-play/act          # 运行一组子 agent 扮演（前端拦截 <agent_call> 后调用）
     入参: { characters:[{name, focus}], chatId, searchText, context }
     出参: { runId, actors:[{character, monologue, model, tokens}] }
GET  /api/agent-play/run/:runId/events   # 事件流（时间线）
POST /api/agent-play/cancel       # 取消 run
GET  /api/agent-play/config       # 读取/校验配置
POST /api/agent-play/config       # 保存配置
```

## 9. 模型配置（设置项, 前后端共享）

```jsonc
{
  "apiUrl": "", "apiKey": "",        // OpenAI 兼容 API（扮演模型）
  "actorModel": "",                   // 便宜模型（子 agent 扮演）
  "concurrency": 3,                   // 子 agent 并发上限
  "animaApiUrl": "",                  // ANIMA /query 地址
  "animaCollectionId": "",            // ANIMA 集合 id
  "memoryLimit": 5,                   // 每角色记忆条数上限
  "maxAgentCalls": 3,                 // 主模型每轮最多调用子 agent 次数
  "publicMemory": false,              // public 记忆共享（默认关）
  "timeoutMs": 45000                  // 子 agent 超时
}
```

## 10. 与"值班与乱入"脚本的分工

| 职责 | 归属 |
|---|---|
| 时间/时段/排班/夜班持有者 | 值班与乱入脚本（现有） |
| 乱入检定（掷骰/候选/豁免） | 值班与乱入脚本（现有） |
| 场景记录/存在时间（写世界书） | 值班与乱入脚本（现有） |
| 剧情时间统一注入 | agent-play 前端 |
| 世界书条目关键字分配（设定） | agent-play 前端（组装） |
| 主 agent（正文生成 + 决策调子 agent） | **主模型**（主预设改法 1） |
| 子 agent 并发扮演 | agent-play 服务器插件 |
| ANIMA 记忆查询（按人物, 仅子 agent 层） | agent-play 服务器插件 |

agent-play 通过 `getVariables({type:'script', script_id: 值班与乱入的id})` 读取乱入/排班/时间上下文。

## 11. 待确认项（实施前定）

1. **世界书匹配机制（研究中）**：条目 `strategy.keys` 结构；公共条目是否真的无 keys。→ 用户研究后定。
2. **ANIMA `/query` 的 `apiConfig`（向量模型）来源**：复用 agent-play 的 API 配置 vs 读 ANIMA 前端扩展设置。→ 建议复用 agent-play 配置。
3. **集合 id（animaCollectionId）**：手动填 vs 复刻 `getSmartCollectionId`。→ 先手动填。
4. **重大事件库写入方式（二期）**：A 改 ANIMA 总结分流 vs B 插件后台写入。
5. **主模型 <agent_call> 的可靠性**：模型可能不按格式输出标记 → 前端要有容错（解析失败则本轮不推演, 直接放行）。

## 12. 实施步骤

1. 后端骨架：plugins/agent-play/（package.json + index.js + init(router)），先挂 /config 端点。
2. 后端跑通"单角色扮演"：/act 传 { name, focus } → 组输入（世界书+消息）→ 调 actorModel → 返回 monologue。
3. 前端骨架：extensions/third-party/agent-play/（manifest + index.js + 设置面板）。
4. 前端实现世界书关键字分配 → 组装上下文 → 调 /act。
5. 加 ANIMA 记忆：anima-client.js → 联调 /query → 按人物过滤。
6. 加并发扮演：actor.js（Promise.all + 并发限制 + 超时 + 失败降级）。
7. 主预设加"主 agent 模式"段 + 前端拦截 `<agent_call>` → 注入独白 → 继续生成。
8. 加事件流/时间线（events.js + 前端 UI）。
9. 接乱入/排班上下文（读值班脚本变量）。
10. 测试 + 调优。

## 13. 测试与验收

| 用例 | 预期 |
|---|---|
| 主模型输出 <agent_call> | 前端拦截 → 后端并发扮演 → 独白注入 → 继续生成 |
| 主模型不输出标记 | 直接生成, 不触发子 agent |
| 子 agent 输入含 世界书+记忆+时间 | 按 keys 分配、记忆按人物、时间插件算好 |
| ANIMA /query 失败 | 降级（不注入记忆）, 扮演照常 |
| 某角色扮演失败 | 只跳过该角色 |
| 并发上限 | 同时请求数 ≤ concurrency |
| 超时 | 45s 后中止并放行, 不卡发送 |
| <agent_call> 解析失败 | 本轮不推演, 直接放行 |
| 主预设其余规则 | 照常生效（改法 1 保留） |

## 14. 风险与回退

- **主模型不按格式输出 <agent_call>**：容错解析 + 失败放行；可加"上一轮对话末尾提示使用标记"。
- **主 agent 循环慢/卡**：maxAgentCalls 上限 + 超时 + 降级直接生成。
- **token 成本**：主模型多轮 + 子 agent N 个 + ANIMA /query(N)。便宜模型控制；可关子 agent（回退纯主模型）。
- **防全知**：主模型不查 ANIMA + 独白只含角色视角。
- **回退**：主预设去掉"主 agent 模式"段即回到纯主模型；插件开关默认关。
